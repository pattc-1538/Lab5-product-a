## 2. ユーザーストーリー

市場管理者として、手数料・取引権限・許可要件・支払期限・完納奨励金率などの業務規程の値を、適用開始日つきの新しい版として自分で公開したい。なぜなら、規程が改定されてもソフトウェアを改修せずに反映でき、過去の取引や仕切の数値は変えずに済むからだ。

## 3. 背景・目的

- **現状の課題**：市場は 2020 年の卸売市場法改正を受けて独自の業務規程を定めたばかりで、汎用の「せり市場」システムではこの規程に合わない（system-overview §2 #2）。手数料・取引権限・許可要件などの数値やルールを支えるツールがない。
- [ASSUMPTION] 現在は担当者が紙の業務規程を参照するか記憶に頼り、手計算している。規程の変更は年に数回、年度初めに集中する（一般的な市場運営からの推定。§10 #1 で顧客確認）。
- **目的 1（最重要）**：業務規程の数値・ルールを**適用開始日つきのパラメータ**としてシステムに持ち、規程が変わっても**ソフトウェアを改修せず**、新しい版を公開するだけで対応できるようにする（system-overview §3 #2）。
- **目的 2**：パラメータは上書きせず、明日以降に始まる新しい版として公開する。取引・仕切・許可申請はそれぞれの日付時点で有効な版で計算・判定されるため、過去の数値は変わらない（ADR-003、market-rule-catalog R-08）。
- **目的 3**：後続ストーリーが参照する唯一のデータ源とする。取引権限チェック（E-03-S01／E-03-S02）、仕切（E-04-S01）、許可・承認（E-01-S01）、完納奨励金（E-04-S03）。
- **効果**：規程変更をシステム管理者（市場管理者）自身が反映でき、改修の費用と期間が不要になる。変更履歴から「いつ・誰が・何を」変えたかを確認できる。

## 5. スコープ

**対象内**（すべて同じ「適用開始日つきの新しい版を公開する」方式。上書き・遡及変更なし）
- 手数料・税率：委託手数料率、消費税率（水産物・手数料）、表示のみの端数処理（切捨て）（R-03、LAB-2 実装済み）
- 取引権限：販売チャネル（相対取引／せり）× 権限区分（第一種／第二種）の可否と、不可の理由・規程条文（R-02、LAB-2 実装済み）
- 種別区分：参加者種別 → 権限区分・許可区分（許可／承認／不要）（R-01、R-04。許可区分は LAB-4 で追加）
- 許可・承認要件：要件コード・要件名・確認方法（書類／保証金／審査／有効期間上限）・最低金額・規程条文（R-05、LAB-4 で追加・未実装）
- **支払期限**：買受代金の支払期限のルール（E-04-S02 が参照）。SPEC-PA-105 に未設計のため基本設計で画面を追加する
- **完納奨励金率**：期間ごとの奨励金率と対象条件（E-04-S03 が参照）。同上、基本設計で追加する
- 現在の値（本日適用中）・予約中の版・終了した版の表示、予約件数の通知
- 公開前の確認ダイアログ、変更履歴（区分・内容・適用期間・状態・登録者・登録日時）

**対象外**
- 予約中の版の取消・修正（同じ日付の版を公開すると期間重複エラー。後の日付の版で置き換えるのみ）→ §10 で顧客に必要性を確認
- 許可・承認要件の廃止（新しい版で置き換えるのみ）→ §10 で顧客に必要性を確認
- ルールの**構造**の変更（端数処理方式の追加、新しい販売チャネル、第 3 の許可区分など）：パラメータではなくソフトウェア改修（LAB-1 見積の前提）
- パラメータを使う計算・判定そのもの：取引権限チェック → E-03-S01、仕切計算 → E-04-S01、支払期限の管理 → E-04-S02、完納奨励金の計算 → E-04-S03、許可・承認の手続き → E-01-S01
- 公開に対する承認フロー（二重チェック）：市場管理者が単独で公開する

## 6. 主な業務フロー

> 出典：SPEC-PA-105 v0.2.0（PA_BUSINESS_RULE_PARAMS）、SPEC-PA-204 v0.2.0（PA_PUBLISH_RULE_PARAMETER_TECH）

**基本フロー（新しい版の公開。全タブ共通）**
1. 市場管理者が業務規程パラメータ画面を開く。予約中の版があれば「N件の版が適用待ちです」と表示される。
2. タブ（手数料・税率／取引権限／種別区分／許可・承認要件／支払期限／完納奨励金率／変更履歴）を選び、本日適用中の値と予約中・終了した版を確認する。
3. 新しい値、**適用開始日（市場の営業日で明日以降）**、**変更理由（全タブ必須）**を入力する。
4. 「新しい版を公開」を押すと確認ダイアログが開き、内容の要約と「現在の版は前日までで終了し、上書きはされません。」を表示する。
5. 「公開する」を押すと、新しい版が「予約」として保存され、現在の版の終了日が新しい版の開始日の前日になる。実行者・日時・内容は監査ログに残る。
6. 適用開始日になると新しい版が「適用中」になり、取引・仕切・許可申請・支払期限・奨励金計算はその日付以降、新しい版で処理される。
- 公開は市場管理者 1 名で完結し、二人目の承認は不要（確認ダイアログ・監査ログ・開始日前の差し替えで誤りに備える）。
- 当日適用は不可。急ぎの修正も明日以降の版として公開する（当日の取引が新旧 2 つのルールに分かれるのを防ぐ。R-08）。

**代替・例外フロー**
- 入力エラー（必須未入力、範囲外、形式不正）：欄の横にエラーを表示し、確認ダイアログを開かない。
- 適用開始日が本日以前、または現在の版・予約中の版の開始日以前：公開せず M_51 を表示。
- 2 人が同時に同じ項目を公開して期間が重なる：後の公開を拒否し M_50 を表示。
- 不正な値の送信（例：承認に確認方法「審査」）：DB の制約で拒否し M_03 を表示。
- 確認ダイアログで「やめる」：ダイアログを閉じ、入力内容は保持する。
- セッション切れ：M_01 を表示してログイン画面へ戻す。
- 卸売業者 担当者が URL を直接開く：ダッシュボードへ戻す。API を直接呼んでも権限エラーで拒否する。

## 7. データ要件

> 型・桁数・制約は基本設計で確定する。全タブ共通で、各版は `適用開始日`・`適用終了日`（次の版の開始日で自動設定）・`変更理由`・`登録者`・`登録日時`・`仮フラグ`（初期データのみ true）を持つ。

| 項目 | 取得元 | 表示のみ／編集可 | 備考 |
| --- | --- | --- | --- |
| 委託手数料率・消費税率（水産物／手数料） | 本画面で入力 | 編集可（新しい版として） | 0〜100%、小数 2 桁まで、ベーシスポイントで保存（SPEC-PA-105 B） |
| 端数処理 | 固定（切捨て） | 表示のみ | 方式の変更はソフトウェア改修 |
| 取引権限（チャネル × 権限区分 → 可／不可、不可の理由・規程条文） | 本画面で入力 | 編集可 | 理由は取引入力画面に表示（SPEC-PA-105 C） |
| 種別区分（種別 → 権限区分・許可区分） | 本画面で入力 | 編集可 | SPEC-PA-105 D |
| 許可・承認要件（区分、要件コード、要件名、確認方法、最低金額、有効期間上限、規程条文） | 本画面で入力 | 編集可 | 承認に「審査」は不可（SPEC-PA-105 E） |
| 支払期限（締め日、締め日から支払期限までの日数） | 本画面で入力 | 編集可 | 締め日は複数可（例：10日・20日・月末）。具体値は §10 #5 |
| 完納奨励金率（対象期間の単位、奨励金率 %） | 本画面で入力 | 編集可 | 期間（月）ごとに 1 つの率。対象条件（期間内の買受代金を期限までに全額支払い）と率の値は §10 #6 |
| 変更履歴 | 上記すべての版 | 表示のみ | 新しい順。区分に「支払期限」「完納奨励金率」を追加 |

- 版は**削除しない**（永久保存）。過去の取引・仕切・申請はいつでもその日付の版を参照できる。件数は年に数十件程度で容量の問題はない。
- 本ストーリーの出力：各パラメータの「指定日に有効な版」を返す参照手段。E-01-S01、E-03-S01、E-03-S02、E-04-S01、E-04-S02、E-04-S03 が利用する。

## 8. 技術的制約・非機能面の考慮事項

- **対象端末**：事務所の PC ブラウザ。タブレット対応は不要（売場では使わない）。
- **日付の基準**：「本日・明日」は日本時間（JST）の暦日で判定し、0:00 に切り替わる。早朝のせりも同じ暦日に含まれる（LAB-2 実装と同じ）。
- **遡及変更の禁止**：適用開始日が明日以降であることを画面（入力チェック）と DB（`assert_future_valid_from`）の両方で検査する。画面だけの検査にしない（LAB-2 の不具合 #1 の再発防止）。
- **期間の重複防止**：同じ項目の版の期間が重ならないことを DB の排他制約で保証し、同時公開は後の方を拒否する（R-08）。
- **NFR-004 セキュリティ**：市場管理者だけが公開できる（画面と DB の両方で権限チェック）。すべての公開を監査ログに記録する。
- **NFR-005 計算精度**：率はベーシスポイント（整数）で保存し、浮動小数の誤差を出さない。仕切・完納奨励金の計算は対象日の版を使う。
- **NFR-006 法令・規程**：値は業務規程に従う。規程の条文番号を版ごとに記録できる。
- **NFR-007 データ管理**：版は削除しない。日次バックアップの対象。
- **初期データ**：現在の初期データ（「仮」フラグ付き）は、本番稼働前に顧客から受け取った実際の業務規程の値に置き換える。Sun* がデータ移行フェーズ（2027-04-01〜04-05）で投入し、本番稼働時点で「仮」の版を残さない。
- NFR-001（性能）の特別な要件はない。利用頻度が低く、データ量も少ない。

## 9. 受入基準

**共通（版の公開）**
- [ ] Given 市場管理者がログインしている、When 業務規程パラメータ画面を開く、Then 全タブで本日適用中の値・予約中の版・終了した版が適用期間つきで表示され、予約中の版があれば「N件の版が適用待ちです」が表示される。
- [ ] Given 有効な入力（適用開始日＝明日以降、変更理由あり）、When 確認ダイアログで「公開する」を押す、Then 新しい版が「予約」で保存され、現在の版の終了日が新しい版の開始日の前日になり、既存の版の値は一切変わらない。
- [ ] Given 新しい版の適用開始日になった、When 取引・仕切・許可申請などがその日付で処理される、Then 新しい版の値が使われ、開始日より前の日付の処理は旧版の値のまま変わらない。
- [ ] Given 適用開始日が本日以前、When 公開する、Then 保存されず M_51 が表示される。画面の検査を回避して API を直接呼んでも DB で拒否される。
- [ ] Given 予約中の版がある、When その開始日以前の日付で同じ項目を公開する、Then 保存されず M_51 が表示される。
- [ ] Given 2 人が同時に同じ項目を同じ期間で公開する、When 両方が「公開する」を押す、Then 1 件だけ保存され、もう一方には M_50 が表示される。
- [ ] Given 変更理由が空、または値が範囲外（率が 0〜100% の外、小数 3 桁以上など）、When 「新しい版を公開」を押す、Then 欄の横にエラーが表示され、確認ダイアログは開かない。
- [ ] Given 確認ダイアログ、When 「やめる」を押す、Then ダイアログが閉じ、入力内容が残っている。

**タブ別**
- [ ] Given 手数料・税率タブ、When 5.5% と入力して公開する、Then 550（ベーシスポイント）として保存され、画面には 5.5% と表示される。
- [ ] Given 取引権限タブ、When ある区分・チャネルを「不可」にして理由を入れて公開する、Then 適用開始日以降の取引入力で、その理由が不可の理由として表示される（E-03-S01 と結合して確認）。
- [ ] Given 許可・承認要件タブで区分＝承認、When 確認方法を選ぶ、Then「審査」は選べない。偽の送信をしても DB で拒否され M_03 が表示される。
- [ ] Given 許可・承認要件タブで確認方法＝保証金、When 最低金額を空のまま公開する、Then 保存されずエラーが表示される。
- [ ] Given 支払期限タブ、When 締め日（複数可）と支払期限までの日数を入れて公開する、Then 新しい版として保存され、E-04-S02 が指定日の版を参照できる。
- [ ] Given 完納奨励金率タブ、When 期間ごとの率を入れて公開する、Then 新しい版として保存され、E-04-S03 が指定期間の版を参照できる。

**権限・監査・データ**
- [ ] Given 卸売業者 担当者でログイン、When メニューを見る／URL を直接開く／公開 API を直接呼ぶ、Then メニューは表示されず、URL はダッシュボードへ戻り、API は権限エラーになり DB に変更が残らない。
- [ ] Given 任意のタブでの公開、When 公開が成功する、Then 実行者・日時・内容・変更理由が監査ログと変更履歴タブに残り、新しい順で表示される。
- [ ] Given 公開済みの版、When どの画面・API を使っても、Then 版を削除・上書きする手段がない。
- [ ] Given 本番稼働日、When パラメータ画面を開く、Then 適用中の版に「仮」の版が残っていない（データ移行で実際の業務規程の値を投入済み）。
