## 2. ユーザーストーリー

卸売業者 担当者として、水揚げされた漁獲物を売場のタブレットからその場でロットとして上場し、残数量と販売状況を全員でリアルタイムに確認したい。なぜなら、早朝のせりを遅らせずに販売を始め、すべての取引をロットと出荷者にひもづけて仕切の精算先を確実にしたいからだ。

## 3. 背景・目的

- **現状の課題**：取引は電話・FAX・手書きの台帳で管理され、当日の取引状況をリアルタイムに把握できず、転記や精算の誤りが起きる（system-overview §2 #1、QA-001 で顧客確認中）。
- [ASSUMPTION] 現在、入荷は担当者が水揚げ時に入荷伝票や岸壁の黒板に手書きし、あとで台帳に転記している（一般的な産地市場の運用からの推定。§10 #1 で顧客確認）。
- **目的**：取引の流れの最初の工程を電子化する。漁船から届いた漁獲物を、出荷者・品目・数量・目視の鮮度・市場の手書き符号つきの「ロット」として上場する。ロットは相対取引（E-03-S01）とせり（E-03-S02）の販売対象であり、仕切（E-04-S01）でどの出荷者に精算するかの根拠になる（system-overview §3 #1）。
- **重視する価値**（いずれも重要）：
  1. **水揚げ時に素早く入力できる**こと。早朝のせりを遅らせない。
  2. **残数量をリアルタイムに把握できる**こと。ロットごとの未販売／一部販売／販売済を事務所と売場が同じ画面で見られる。
  3. **ロット → 出荷者の追跡**。すべての取引がロットにひもづき、仕切で誰に精算するかが確実にわかる。

## 4. 対象ユーザー

| ROLE-ID | ロール | 利用場面 | 権限 |
| --- | --- | --- | --- |
| ROLE-002 | 卸売業者 担当者 | 早朝の水揚げ時に、売場（岸壁）のタブレットでロットを上場する。1 日あたり約 10 ロット、最大 10 名が同時に入力しうる | 上場（登録）・本日のロット一覧の閲覧 |
| ROLE-001 | 市場管理者 | 事務所の PC で本日のロット一覧と販売状況を確認する | 閲覧のみ（「閲覧のみ — 上場の登録は卸売業者 担当者が行います」を表示） |

- 主端末は**売場のタブレット**。大きなボタン、数字キーボード、片手でも押しやすい配置を前提とする。PC は閲覧用。
- 1 日のロット数は少ない（約 10）が、同時入力者は最大 10 名。同時登録でもロット番号が重複しないことが重要。

## 5. スコープ

**対象内**
- ロットの上場（登録）：出荷者、品目、数量、単位（品目の単位を初期値に、手で変更可）、鮮度（目視判定）、手書き符号、市場日（初期値＝本日）
- **鮮度の選択肢は品目マスタ（E-01-S03）の鮮度区分から読む**。初期値なし、自動判定なし（R-11）
- 本日の上場ロット一覧：ロット番号、出荷者／品目、数量、残数量（うち承認待ち数量）、鮮度、符号、販売状況（未販売／一部販売／販売済）
- **未販売ロットの取消**：理由を必須とし、削除せず「取消」状態にする（R-09）。誤入力は取消して新しいロットを上場する
- 権限：登録・取消は卸売業者 担当者、市場管理者は閲覧のみ

**対象外**
- ロットの修正（取消＋再登録で対応）
- 一部でも販売されたロットの取消（取引の取消が先。E-03-S01／E-03-S02 の範囲）
- 鮮度区分そのものの登録・変更 → E-01-S03（Item master）。出荷者の登録 → E-01-S02
- 取引の記録と残数量の減算 → E-03-S01／E-03-S02（本ストーリーは残数量を表示するだけ）
- **手書き符号の写真添付**：提案書 v2 で対象外と明記しているため、変更要求（CR）の候補とする。顧客が必要とすれば `pm-control-change` で扱う（§10 #5）
- 写真からの文字認識（OCR）や鮮度の自動判定
- 過去日のロットの一覧・検索 → E-05-S01（Trade inquiry）

## 6. 主な業務フロー

> 出典：SPEC-PA-101 v0.1.0（PA_LOT_LISTING）。取消・鮮度区分マスタは本ストーリーで追加（§10 #2）

**基本フロー（上場）**
1. 卸売業者 担当者が売場のタブレットで上場画面を開く。左に登録フォーム、右に本日の上場ロット一覧が表示される。
2. 出荷者と品目を選ぶ。単位は品目の単位が自動で入る（変更可）。
3. 数量を入力し、鮮度を品目マスタの区分から 1 つ選ぶ（初期値なし）。手書き符号があれば原文どおり入力する。
4. 市場日は本日が初期値。紙で記録した分を後から入力するときは**過去日（最大 7 日前まで）**を選ぶ。未来日は選べない。
5. 「上場する」を押すと、ロット番号が採番され「L-xxxx を上場しました」と表示される。フォームは次のロット用に空になり（市場日は保持）、一覧と残数量が更新される。残数量は数量と同じ値で始まる。

**基本フロー（取消）**
1. 卸売業者 担当者が一覧から未販売のロットを選び「取消」を押す。
2. 取消理由を入力して確定すると、ロットは削除されず「取消」状態になり、販売対象から外れる。実行者・日時・理由は監査ログに残る。誰が登録したロットでも、卸売業者 担当者なら取消できる。

**代替・例外フロー**
- 必須項目の未入力・形式不正（数量が 0 以下、小数 2 桁以上、符号が 100 文字超など）：欄の横にエラーを表示し、最初のエラー欄にフォーカスする。登録しない。
- 市場日が未来日、または 8 日以上前：登録せずエラーを表示する。
- 一部でも販売済みのロットの取消：拒否し「販売済みの取引を先に取り消してください」を表示する。
- 市場管理者が登録・取消を試みる（API の直接呼び出しを含む）：権限エラー（M_02）、DB にも変更を残さない。
- セッション切れ：M_01 を表示してログイン画面へ戻す。
- 通信障害：紙の上場記録で運用を続け、復旧後に過去日として入力する（NFR-003）。

## 7. データ要件

> 型・桁数・制約は基本設計で確定する。

| 項目 | 取得元 | 表示のみ／編集可 | 備考 |
| --- | --- | --- | --- |
| ロット番号 | システム採番 | 表示のみ | 「L-」＋ 4 桁。**市場日ごとに L-0001 から採番**し、（市場日＋ロット番号）で一意。同時登録でも重複しない |
| 出荷者 | 出荷者マスタ（E-01-S02） | 登録時に選択 | 仕切の精算先 |
| 品目 | 品目マスタ（E-01-S03） | 登録時に選択 | |
| 数量 | 本画面で入力 | 登録時に入力 | 0 より大きい。**kg は小数 1 桁まで、箱・尾は整数**。全角数字・カンマは正規化 |
| 単位 | 品目マスタの単位を初期値 | 登録時に変更可 | kg／箱／尾 |
| 鮮度 | 品目マスタの鮮度区分（E-01-S03） | 登録時に選択 | 初期値なし（§10 #3） |
| 手書き符号 | 本画面で入力 | 登録時に入力（任意） | 原文どおり、100 文字以内 |
| 市場日 | 本画面で入力 | 登録時に入力 | 初期値＝本日（JST）。本日〜7 日前まで |
| 残数量・うち承認待ち数量 | 取引（E-03-S01／E-03-S02）から算出 | 表示のみ | 登録時は数量と同じ |
| 販売状況 | 残数量から算出 | 表示のみ | 未販売／一部販売／販売済／取消 |
| 状態・取消理由・取消者・取消日時 | 取消操作 | 取消時に入力（理由必須） | ロットは削除しない（R-09） |
| 登録者・登録日時 | システム | 表示のみ | 監査ログにも記録 |

- 出力：ロットは E-03-S01／E-03-S02 の販売対象、E-04-S01 の精算先の根拠、E-05-S01 の照会対象になる。
- 取消済みのロットは販売対象に出さないが、一覧と照会には「取消」として残す。

## 8. 技術的制約・非機能面の考慮事項

- **対象端末**：売場のタブレット（主）、事務所の PC（閲覧）。タブレットではタッチしやすい大きさのボタン（主ボタンは高さ 56px 程度）と数字キーボードを使う。
- **自動更新**：本日のロット一覧・残数量・販売状況は、他の担当者の上場・販売・取消を**10 秒以内に自動で反映**する（画面の再読み込み不要）。
- **同時登録**：最大 10 名が同時に上場しても、ロット番号が重複しないことを DB 側で保証する。
- **NFR-001 性能**：上場の登録と一覧表示は 3 秒程度以内（QA-002 で確定）。
- **NFR-002 可用性**：早朝のせりの時間帯に利用できること。
- **NFR-003 運用性**：オフライン入力は作らない。通信障害時は紙の上場記録で運用し、復旧後に過去日（7 日前まで）として入力する。
- **NFR-004 セキュリティ**：登録・取消は卸売業者 担当者だけ（画面と DB の両方でチェック）。上場・取消は監査ログに記録する。
- **NFR-007 データ管理**：ロットは日次バックアップの対象。ロットは削除しない。
- 鮮度・符号は人が入力し、システムは記録するだけ（R-11）。自動判定・OCR は行わない。

## 9. 受入基準

**上場**
- [ ] Given 卸売業者 担当者がタブレットでログインしている、When 出荷者・品目・数量・鮮度を入力して「上場する」を押す、Then 「L-xxxx を上場しました」が表示され、ロットが本日の一覧の先頭に「未販売」、残数量＝数量で表示され、フォームは市場日を残して空になる。
- [ ] Given 品目を選ぶ、When 品目が決まる、Then 単位がその品目の単位に自動で切り替わり、手で変更もできる。
- [ ] Given 鮮度欄、When 画面を開く、Then 選択肢は品目マスタの鮮度区分で、初期値は選ばれていない。未選択のまま登録すると「鮮度を選択してください。」が表示される。
- [ ] Given 単位が kg、When 12.5 を入力する、Then 登録できる。Given 単位が箱または尾、When 1.5 を入力する、Then 整数で入力するようエラーが表示される。数量 0 以下も登録できない。
- [ ] Given 全角数字やカンマを含む数量（例：「１，２００」）、When 登録する、Then 1200 として保存される。
- [ ] Given 市場日に本日〜7 日前の日付、When 登録する、Then その市場日のロットとして保存される。Given 未来日または 8 日以上前、When 登録する、Then エラーで保存されない。
- [ ] Given 同じ市場日、When 10 名が同時に上場する、Then ロット番号は重複せず、翌日の最初のロットは L-0001 から始まる。

**一覧・自動更新**
- [ ] Given 2 台のタブレットで一覧を開いている、When 片方で上場する、または取引で残数量が減る、Then もう片方の一覧に 10 秒以内に反映される。
- [ ] Given 一覧、When 残数量が数量と同じ／0 より大きく数量未満／0、Then 販売状況はそれぞれ「未販売」「一部販売」「販売済」と表示される。承認待ちの取引があれば「うち承認待ち N」が表示される。

**取消**
- [ ] Given 未販売のロット、When 卸売業者 担当者（登録者以外を含む）が理由を入力して取消す、Then ロットは削除されず「取消」と表示され、販売対象（取引入力の選択肢）に出なくなる。
- [ ] Given 一部でも販売済みのロット、When 取消を押す、Then 拒否され「販売済みの取引を先に取り消してください」が表示される。
- [ ] Given 取消理由が空、When 確定する、Then 取消されずエラーが表示される。

**権限・監査**
- [ ] Given 市場管理者でログイン、When 上場画面を開く、Then 一覧だけが全幅で表示され「閲覧のみ」の帯が出る。登録・取消の API を直接呼んでも M_02 になり、DB に変更が残らない。
- [ ] Given 上場または取消、When 実行する、Then 実行者・日時・内容（取消は理由も）が監査ログに残る。
