## 2. ユーザーストーリー

卸売業者 担当者として、せりで落札されたロットの結果を売場のタブレットでその場に記録し、共通の権限チェックで落札者の取引権限を確認したい。なぜなら、落札票の転記をなくしてせり結果をすぐに仕切と売掛金へつなげ、業務規程に反する落札を見逃さないためだ。

## 3. 背景・目的

- **現状**：せりは市場の売場で口頭・手振りで行われる。せり人がせり台帳（落札票）に手書きで記録し、せりの後に事務所が台帳へ転記している（PM 確認、2026-11-23）。転記の手間と誤りがあり、せりの結果をリアルタイムに把握できない（system-overview §2 #1）。
- **目的 1**：せりの**結果**（ロットごとの落札者・落札価格・数量）をシステムに記録する。せりそのものの進行（電子せり）はシステム化しない（提案書の論点 01、Base シナリオ）。
- **目的 2**：記録時に、E-03-S01 で作る**共通の取引権限チェック**で落札者の取引権限（せりチャネル）を確認し、業務規程に反する落札を見逃さない（system-overview §3 #3、R-06）。
- **目的 3**：せりの取引は相対取引と同じ取引データとして持ち、仕切（E-04-S01）・売掛金（E-04-S02）・照会（E-05）の元データにする。

## 4. 対象ユーザー

| ROLE-ID | ロール | 利用場面 | 権限 |
| --- | --- | --- | --- |
| ROLE-002 | 卸売業者 担当者 | せりの間、売場でせり人の横に立ち、ロットが落札されるたびにタブレットで結果を記録する。1 日 10 件以下、同時入力は 1〜2 名 | 記録・取消・本日のせり結果の閲覧 |
| ROLE-001 | 市場管理者 | 事務所の PC でせり結果を確認する | 閲覧のみ |

- 主端末は**売場のタブレット**。せりのテンポを止めないよう、少ない操作で 1 件を記録できることが重要。
- せり人の手書きの落札票は、通信障害時の予備として残す（NFR-003）。

## 5. スコープ

**対象内**
- せり結果の記録：ロット、落札者（買受人）、落札単価（税抜）、取引日。数量は**ロットの残数量全部**（せりはロット単位で売る）。金額＝⌊数量 × 単価⌋ をサーバーで計算する
- 記録時の取引権限チェック：E-03-S01 の**共通権限チェック**をせりチャネルで呼ぶ（新しい判定ロジックは作らない）
- 権限が「✕」で例外を認める理由なら、E-03-S01 と**同じ例外登録・承認の仕組み**で「承認待ち」として記録する。市場管理者は同じ例外承認画面で処理する。例外を認めない理由なら記録できず、ロットは再度せりにかけるか相対取引で売る
- 本日のせり結果一覧（確定／承認待ち／却下／取消）
- 取消：仕切前の確定取引を理由つきで取り消し、数量をロットへ戻す（R-09）

**対象外**
- 電子せり（入札・せり値の進行・せり順の管理）：提案書の Max シナリオ（+33 人日）
- 1 つのロットを複数の落札者に分けて売ること（数量は残数量全部に固定）
- せりのルール（せり順、最低価格など）の管理：market-rule-catalog で対象外
- 権限チェックそのもの・例外承認画面 → E-03-S01（本ストーリーは呼び出すだけ）

## 6. 主な業務フロー

> LAB-4 に画面仕様はない（market-rule-catalog「せりは結果記録のみ、画面未作成」）。基本設計で SPEC-PA-102 の構成を流用して作成する。

**基本フロー（記録）**
1. 卸売業者 担当者が売場のタブレットでせり結果画面を開く。残数量があり取消されていないロットが選択肢に出る（相対取引で一部売れたロットも含む）。
2. せりにかかっているロットを選ぶ。数量はそのロットの残数量全部が自動で入る（変更不可）。
3. 落札者を選ぶと、共通の取引権限チェック（せりチャネル）が動き、「✓ 取引可」または「✕ 取引不可」と理由を表示する。
4. 落札単価（税抜）を入力して「登録する」を押す。サーバーで権限を再チェックし、金額を計算して「確定」として保存する。ロットの残数量は 0（販売済）になる。
5. 取引日は本日が初期値。通信障害で落札票から後で入力するときは、本日〜7 日前、かつロットの市場日以降を選ぶ。

**基本フロー（例外・取消）**
- 権限が「✕」で例外を認める理由なら、理由を書いて「承認待ち」として記録する。以降の承認・却下・仕切での扱いは E-03-S01 と同じ。
- 仕切前の確定取引は理由つきで取消でき、数量はロットへ戻る（再度せりまたは相対取引で売れる）。

**代替・例外フロー**
- 例外を認めない理由（停止・買受人でない・規程未設定・許可の停止／取消）：記録できない。ロットは残ったままで、再度せりにかけるか相対取引で売る。
- 確認から保存までの間に、他の担当者が同じロットを相対取引で売った：残数量が変わったため保存せず、最新の残数量で確認し直すよう表示する（二重販売の防止）。
- 単価が 0 以下・小数、取引日が範囲外：欄の横にエラー。
- 仕切済み・取消済み・承認待ちの取引の取消：E-03-S01 と同じく拒否する。
- 市場管理者が記録・取消を試みる（API の直接呼び出しを含む）：M_02、DB に変更を残さない。

## 7. データ要件

> 型・桁数・制約は基本設計で確定する。相対取引（E-03-S01）と**同じ取引データ**に、販売チャネル＝せりとして保存する。

| 項目 | 取得元 | 表示のみ／編集可 | 備考 |
| --- | --- | --- | --- |
| 取引番号 | システム採番 | 表示のみ | 相対取引と**同じ全体連番** |
| 販売チャネル | 固定（せり） | 表示のみ | |
| ロット | ロット（E-02-S01） | 記録時に選択 | 残数量 > 0、取消されていないもの |
| 落札者（買受人） | 参加者台帳（E-01-S01） | 記録時に選択 | |
| 数量 | ロットの残数量 | 表示のみ | 残数量全部（変更不可） |
| 落札単価（税抜） | 本画面で入力 | 記録時に入力 | 円単位の整数、1〜9,999,999（ADR-006） |
| 金額（税抜） | サーバーで計算 | 表示のみ | ⌊数量 × 単価⌋ |
| 取引日 | 本画面で入力 | 記録時に入力 | 初期値＝本日。本日〜7 日前、かつロットの市場日以降 |
| 権限チェック結果・状態・例外理由・承認／却下・取消の情報 | E-03-S01 と同じ | E-03-S01 と同じ | |
| 登録者・登録日時 | システム | 表示のみ | 監査ログにも記録 |

- 出力：確定したせり取引は相対取引と同じく、仕切（E-04-S01）・売掛金（E-04-S02）・照会と帳票（E-05）の元データになる。

## 8. 技術的制約・非機能面の考慮事項

- **対象端末**：売場のタブレット。PC でも閲覧・記録できる。
- **操作の速さ**：1 件の記録は**約 15 秒以内**に終えられること（ロット選択 → 落札者選択 → 単価入力 → 登録ボタン 1 回）。未販売のロットを一覧の上に並べ、落札者はコード・カナで素早く検索できる。
- **共通権限チェック**：E-03-S01 の判定関数をそのまま使う（ADR-002、R-06）。結果は約 1 秒以内に表示し、保存時に必ず再判定する。
- **二重販売の防止**：保存時にロットの残数量をロックして確認し、確認後に残数量が変わっていれば保存しない。
- **NFR-005 計算精度**：金額は円単位の整数でサーバーが計算する（ADR-006）。
- **NFR-004 セキュリティ**：記録・取消は卸売業者 担当者だけ。記録・例外登録・取消は監査ログに残る。
- **NFR-003 運用性**：通信障害時はせり人の落札票で運用し、復旧後に取引日を過去日として入力する。権限はその日付で判定する。
- NFR-001（性能）：記録は 3 秒程度以内。取引は削除しない（R-09）、日次バックアップの対象（NFR-007）。

## 9. 受入基準

**記録**
- [ ] Given 卸売業者 担当者がタブレットでログインしている、When せり結果画面を開く、Then 残数量があり取消されていないロットが、未販売のものを上にして表示される。
- [ ] Given 残数量 20 kg のロット（相対取引で一部販売済みを含む）、When 取引可の落札者と単価 1,500 円で登録する、Then 数量 20 kg・金額 30,000 円の「確定」せり取引として保存され、ロットは「販売済」になり、取引番号は相対取引と同じ連番で振られる。
- [ ] Given せり結果の登録、When 数量欄を見る、Then 残数量全部が入っていて変更できない。
- [ ] Given 単価が 0 以下・小数、または取引日が未来日・8 日以上前・ロットの市場日より前、When 登録する、Then 保存されない。
- [ ] Given 慣れた担当者、When 1 件を記録する、Then ロット選択から登録完了まで約 15 秒以内で終えられる。

**権限・例外**
- [ ] Given 落札者を選ぶ、When 選択が確定する、Then E-03-S01 と同じ判定関数がせりチャネルで呼ばれ、約 1 秒以内に可否・理由・根拠が表示される。同じ入力なら相対取引入力と同じ結果になる（チャネル以外）。
- [ ] Given 理由が例外可、When 理由を書いて登録する、Then 「承認待ち」で保存され、E-03-S01 の例外承認画面に表示される。承認されれば次の仕切に含まれ、却下されれば数量がロットへ戻る。
- [ ] Given 理由が例外不可、When 登録しようとする、Then 記録できず、ロットの残数量は変わらない。

**同時操作・取消・権限・監査**
- [ ] Given 確認の後、別の担当者が同じロットを相対取引で一部売った、When せり結果を登録する、Then 保存されず、最新の残数量で確認し直すよう表示される。
- [ ] Given 仕切前の確定せり取引、When 理由を書いて取消す、Then 「取消」になり数量がロットへ戻る。
- [ ] Given 市場管理者、When せり結果を記録・取消しようとする（API の直接呼び出しを含む）、Then M_02 になり DB に変更が残らない。
- [ ] Given 記録・例外登録・取消、When 実行する、Then 実行者・日時・内容・理由が監査ログに残る。
