## 2. ユーザーストーリー

市場管理者として、参加者を種別・権限区分つきで登録し、仲卸の許可（審査あり）と売買参加者の承認（審査なし）を申請から判断まで記録したい。なぜなら、有効な許可・承認を持つ参加者だけが取引できる状態を保ち、業務規程に反する取引を入力時点で止めたいからだ。

## 3. 背景・目的

- **現状の課題**：4 種類の参加者（仲卸・売買参加者・買出人・卸売業者）のうち、誰がどのチャネル（せり／相対）で誰から買えるかを、紙の台帳と人の記憶で確認している。業務規程に反する取引が見逃されるおそれがある（system-overview §2 #3、QA-001 で顧客確認中）。
- **目的 1**：参加者の種別・権限区分・状態を 1 か所に登録し、取引入力時の権限チェック（E-03-S01）が参照する唯一のデータ源とする。
- **目的 2**：業務規程上の 2 種類の手続き、**許可**（仲卸：要件確認＋審査会による審査あり）と **承認**（売買参加者：要件確認のみ、審査なし）の申請から判断までをシステムで記録し、有効な許可／承認を持つ参加者だけが取引できる状態にする。
- **効果**：権限のない参加者との取引を入力時点で止められる。許可・承認の期限切れや停止を担当者全員が同じ画面で確認できる。

## 4. 対象ユーザー

| ROLE-ID | ロール | 利用場面 | 権限 |
| --- | --- | --- | --- |
| ROLE-001 | 市場管理者 | 事務所の PC で参加者の登録・変更、許可／承認の申請受付・要件確認・判断を行う。頻度は月数回（年度初めの更新時期に集中） | 登録・変更・手続きの全操作 |
| ROLE-002 | 卸売業者 担当者 | 売場のタブレットで「この買い手は今日取引できるか」を素早く確認する | 閲覧のみ（保証金額・判断理由は表示しない） |

- 仲卸・売買参加者・買出人はログインしない。参加者データとして管理される（role-list §1）。

## 5. スコープ

**対象内**
- 参加者台帳：一覧（名称・コード・カナ、種別、許可状態での絞り込み）、詳細、登録・変更（ROLE-001 のみ）
- 種別ごとの権限区分（第一種／第二種／対象外）と必要な許可区分（許可／承認／不要）の表示。値は業務規程パラメータから**読むだけ**
- 許可／承認の手続き：申請受付 → 要件チェックリストの確認 →（許可のみ）審査開始 → 許可・承認／却下
- 許可／承認後の操作：停止・停止解除・取消（理由と効力発生日つき）、期限 30 日前（仮）からの更新申請
- 許可・承認の履歴表示、期限間近・期限切れの表示
- 一覧・詳細での「本日の取引可否」の要約表示（判定は E-03-S01 の共通権限チェックを呼ぶ）

**対象外**
- 書類スキャンファイルの保存（書類番号・受領番号などの参照番号のみ記録）
- 要件・権限区分・期限上限などのパラメータ変更 → E-01-S04（業務規程 parameter settings）
- 取引可否の実際の判定ロジック → E-03-S01（相対取引 recording、共通権限チェック）
- 期限切れのメール等による通知（画面表示のみ）
- 参加者の業務停止（`participants.status`）と許可停止の統合（Q-26 で検討中、本ストーリーでは別々に扱う）

## 6. 主な業務フロー

> 出典：SPEC-PA-104 v0.2.0（PA_PARTICIPANT_LICENSE）、PA_DECIDE_LICENSE_TECH §4.3

**基本フロー（参加者登録）**
1. 市場管理者が参加者を登録する（コード、名称、カナ、種別ほか）。
2. 種別に応じて権限区分と必要な許可区分が自動で決まる（業務規程パラメータ、利用者は選ばない）。買出人・卸売業者は「不要」で、手続きなしで取引できる。

**基本フロー（許可：仲卸）**
1. 市場管理者が申請を受け付ける（申請日、保証金額）→ 状態「申請中」、要件チェックリストは全行「未確認」。
2. 各要件（書類・保証金など）を確認し、適合／不適合と根拠（書類番号など）を記録する。
3. 「審査を開始」→ 状態「審査中」。
4. 要件がすべて適合し、審査会の開催日が決まったら、許可番号・有効期間・審査会開催日を入力して「許可する」→ 状態「有効」。

**基本フロー（承認：売買参加者）**
1.〜2. 許可と同じ（受付 → 要件確認）。
3. 要件がすべて適合したら、審査なしで承認番号・有効期間を入力して「承認する」→ 状態「有効」。

**許可／承認後**
- 停止：理由と効力発生日を入力 → 効力発生日以降の取引は不可（R-12）。それより前の取引には影響しない。
- 停止解除：有効期間内に限り、状態を「有効」に戻す。
- 取消：理由と効力発生日を入力（取り消すと元に戻せない）。
- 更新：有効期限の 30 日前（仮）から新しい申請を受け付ける。新しい有効期間は旧期限の翌日から始まり、空白期間を作らない。
- 有効期限を過ぎた許可は、夜間ジョブを待たずに表示時点で「期限切れ」とする。

**代替・例外フロー**
- 未確認・不適合の要件が残っている → 「許可する／承認する」は押せず、残件数を表示する。
- 申請中・審査中の手続きがすでにある／種別と申請区分が合わない → 受付を拒否する（M_61／M_65）。
- 判断の直前に他の担当者が要件を不適合にした → エラー表示のうえチェックリストを再読込（M_62）。
- 許可で審査会開催日が未入力（M_63）、有効期間が上限超過（M_66）、許可番号の重複や有効・停止中の許可と期間が重なる（M_64）→ 保存しない。
- 却下・停止・取消の理由が空（M_38）、効力発生日が有効期間の開始日より前（M_24）→ 保存しない。
- 他の担当者が先に状態を変えた → エラー表示のうえ画面を再読込（M_61）。
- 卸売業者 担当者が操作を送信した（画面には操作ボタンなし）→ 権限エラー（M_02）、DB 側でも拒否。

## 7. データ要件

> データモデルは PA_MARKET_CORE_DB §4.2、§4.4〜§4.6 に従う。型・桁・制約は設計フェーズで確定する。

| 項目 | 取得元 | 表示のみ／編集可 | 備考 |
| --- | --- | --- | --- |
| コード・名称・カナ・種別・状態（有効／業務停止） | 本機能で入力（`participants`） | 編集可（ROLE-001） | コードは一意 |
| 権限区分（第一種／第二種／対象外）・必要な許可区分（許可／承認／不要） | 業務規程パラメータ（`participant_type_tiers`、E-01-S04） | 表示のみ | 種別と日付で決まる。仮の規則には「仮」を表示。`participants.tier` は使わない |
| 申請区分・申請日・保証金額 | 本機能で入力（`participant_licenses`） | 編集可（ROLE-001） | 保証金額は ROLE-002 に表示しない |
| 手続きの状態（申請中／審査中／有効／却下／停止／期限切れ／取消） | 本機能の操作結果 | 表示のみ | 期限切れは表示時に計算 |
| 許可番号／承認番号・有効期間・審査会開催日 | 本機能で入力（許可・承認時） | 編集可（ROLE-001） | 番号は重複不可。期間の上限は `license_requirements` の `TERM`（仮 60 か月） |
| 判断理由・効力発生日 | 本機能で入力（却下／停止／取消時） | 編集可（ROLE-001） | 判断理由は ROLE-002 に表示しない |
| 要件チェックリストの行 | 業務規程パラメータ（`license_requirements`、申請日時点で有効なもの） | 表示のみ | 確認方法：書類／保証金／審査 |
| 要件ごとの結果・根拠・確認者・日時 | 本機能で入力（`license_condition_checks`） | 編集可（ROLE-001） | 判断前なら何度でも記録できる |
| 本日の取引可否 | E-03-S01 の共通権限チェック（API-TRD-01） | 表示のみ | 要約表示。判定そのものは E-03-S01 |

- 既存の参加者・許可の初期データは、データ移行フェーズ（CSV 取込）で投入する。本ストーリーの対象外。
- 許可・承認のレコードは追記のみで、上書きしない（ADR-007）。更新は新しい申請として登録する。

## 9. 受入基準

> 関連する完了基準：D-001、D-004、D-007、D-010（[define-dod.md](../define-dod.md)）。

**参加者台帳**
- [ ] Given 市場管理者がログインしている、When 必須項目を入力して参加者を登録する、Then 一覧に表示され、種別に応じた権限区分と必要な許可区分がパラメータどおりに表示される（仮の規則には「仮」）。
- [ ] Given 既存と同じコード、When 登録する、Then 保存されずエラーが表示される。
- [ ] Given 一覧画面、When 名称・コード・カナ、種別、許可状態（期限間近 30 日以内を含む）で絞り込む、Then 条件に合う参加者だけが表示され、件数が「N件中 M件を表示」で示される。

**許可（仲卸）**
- [ ] Given 仲卸に申請中・審査中・停止中の手続きがない、When 申請を受け付ける、Then 状態が「申請中」になり、申請日時点のパラメータの要件がすべて「未確認」で並ぶ。
- [ ] Given 許可の申請中、When 審査を開始する、Then 状態が「審査中」になり、ステップ表示が「審査」に進む。
- [ ] Given 審査中で要件がすべて適合、When 許可番号・有効期間・審査会開催日を入力して許可する、Then 状態が「有効」になり、本日の取引可否が「取引可」になる。
- [ ] Given 未確認または不適合の要件が 1 件以上ある、When 詳細画面を開く、Then 「許可する／承認する」は押せず、残件数が表示される。
- [ ] Given 許可の判断で審査会開催日が空、または有効期間が上限超過、When 許可する、Then 保存されず、該当欄にエラー（M_63／M_66）が表示される。

**承認（売買参加者）**
- [ ] Given 売買参加者の申請中で要件がすべて適合、When 承認番号と有効期間を入力して承認する、Then 審査のステップを経ずに状態が「有効」になる（審査開始ボタンと審査会開催日欄は表示されない）。

**許可／承認後の操作**
- [ ] Given 有効な許可、When 理由と効力発生日 X を入力して停止する、Then 取引日 X 以降の取引は権限チェックで不可となり、X より前の取引には影響しない。
- [ ] Given 有効期間内の停止中の許可、When 停止を解除する、Then 状態が「有効」に戻る。
- [ ] Given 有効期限まで 30 日（仮）以内の許可、When 新しい申請を受け付けて許可する、Then 新しい有効期間は旧期限の翌日から始まり、空白期間も重複もない。
- [ ] Given 有効期限を過ぎた許可、When 一覧を開く、Then 夜間処理を待たずに「期限切れ」と表示される。
- [ ] Given 有効または停止中の許可と期間が重なる、または許可番号が重複、When 許可する、Then 保存されずエラー（M_64）が表示される。

**権限・監査**
- [ ] Given 卸売業者 担当者でログイン、When 一覧と詳細を開く、Then 閲覧のみの帯が表示され、登録・操作ボタン、保証金額、判断理由が表示されない。
- [ ] Given 卸売業者 担当者、When 操作のリクエストを直接送る、Then 権限エラー（M_02）となり、DB にも変更が残らない。
- [ ] Given 任意の手続き操作（受付・要件確認・審査開始・許可／承認・却下・停止・停止解除・取消）、When 実行する、Then 実行者・日時・内容が監査ログに残り、履歴欄に新しい順で表示される。
