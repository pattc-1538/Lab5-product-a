## 2. ユーザーストーリー

卸売業者 担当者として、合意した相対取引をその場でロットにひもづけて記録し、保存前に取引日時点の買受人の取引権限を自動で確認したい。なぜなら、業務規程に反する取引と二重販売を入力時点で止め、仕切と売掛金の基礎となる数値を正確に残したいからだ。

## 3. 背景・目的

- **現状の課題**：相対取引（直接交渉による取引）は市場の取引金額の大半を占めるが、電話・FAX で合意し、手書きの台帳に記録している（顧客ブリーフ、system-overview §2 #1）。4 種類の参加者のうち、誰がどのチャネルで誰から買えるかは人が確認しており、業務規程に反する取引を見逃すおそれがある（同 #3）。
- **目的 1**：合意した相対取引を、その場でロット（E-02-S01）にひもづけてシステムに記録する。
- **目的 2**：保存の前に、**取引日時点**での買受人の取引権限を確認する。確認内容は、参加者の状態、許可／承認の有効性、販売チャネル × 権限区分の可否（業務規程パラメータ、E-01-S04）。業務規程に反する取引を入力時点で止める（system-overview §3 #3、R-06）。
- **目的 3**：権限チェックは**共通の 1 つの仕組み**として作り、せり（E-03-S02）と参加者台帳の「本日の取引可否」表示（E-01-S01）でも使う。
- **重視する価値**（いずれも重要）：
  1. **業務規程に反する取引を止める**こと。
  2. **素早く記録でき、二重販売が起きない**こと。ロットの残数量が即時に減り、2 人が同じ数量を売ることはない。
  3. **仕切・売掛金の基礎となる数値が正確**なこと。金額はサーバーで計算し、取引は削除せず取消（理由つき）のみとする（R-09）。

## 4. 対象ユーザー

| ROLE-ID | ロール | 利用場面 | 権限 |
| --- | --- | --- | --- |
| ROLE-002 | 卸売業者 担当者 | 電話・FAX で合意した取引は事務所の PC（キーボード操作）で、売場で合意した取引は売場のタブレットで、合意直後に記録する。1 日あたり約 10 件、最大 10 名が同時に入力しうる | 記録・取消・本日の直近取引の閲覧 |
| ROLE-001 | 市場管理者 | 事務所の PC で直近の取引を確認し、例外登録された取引（承認待ち）を承認または却下する | 相対取引の入力は閲覧のみ（「閲覧のみ — 相対取引の入力は卸売業者 担当者が行います」を表示）。例外の承認・却下 |

- PC とタブレットの両方で使えるレスポンシブな画面とする。PC ではキーボードショートカット（ロット F2、買受人 F3、登録 Ctrl+Enter、クリア Esc）を使える。タブレットでは同じ操作をタッチで行える。
- 件数は少ないが同時入力者は多い。同じロットを同時に売っても残数量を超えないことが重要。
- 仲卸・売買参加者・買出人はログインしない。買受人は参加者データとして選ぶ（role-list §1）。

## 5. スコープ

**対象内**
- 相対取引の記録：ロット（残数量のあるもの）、買受人、数量（ロットの一部も可）、単価（税抜）、取引日（初期値＝本日）。金額＝⌊数量 × 単価⌋ を画面で参考表示し、確定はサーバーで計算する
- **共通の取引権限チェック**：取引日時点の参加者の状態、許可／承認の有効性、チャネル × 権限区分の可否を判定し、理由コード（M_10〜M_16）と根拠（規程条文・適用開始日、許可番号・有効期限）を返す。保存前に画面へ表示し、保存時にも同じ仕組みで再判定する。E-03-S02 と E-01-S01 も利用する
- **例外登録と承認（R-07）**：例外を認める理由（許可・承認の期限切れ、未取得〔停止・取消を除く〕、権限区分の不可）の場合、担当者は理由を書いて「承認待ち」として登録できる。承認待ちはロットの数量を確保するが仕切に入らない。市場管理者は例外承認画面（SPEC-PA-103）で承認（確定）または却下（取消・数量をロットへ戻す）し、理由を記録する
- 本日の直近の相対取引一覧（確定／承認待ち／却下／取消）
- **取消**：仕切前の確定取引を理由つきで取り消し、数量をロットへ戻す。訂正は取消＋再入力で行う（R-09）

**対象外**
- 取引の直接修正（取消＋再入力で対応）
- 仕切済み取引の取消（仕切の取消が先。E-04-S01 の範囲）、承認待ち取引の取消（承認または却下で処理）
- せりの結果記録 → E-03-S02（共通権限チェックは本ストーリーで作り、E-03-S02 が使う）
- 権限チェックが参照するパラメータの登録 → E-01-S04、許可・承認の手続き → E-01-S01
- 過去日の取引照会・帳票 → E-05-S01／E-05-S02
- 例外を認める理由コードの一覧の変更（コードで固定。顧客が必要とすればパラメータ化を検討）

## 6. 主な業務フロー

> 出典：SPEC-PA-102 v0.2.0（PA_AITAI_TRADE_ENTRY）、SPEC-PA-103 v0.2.1（PA_TRADE_EXCEPTION_REVIEW）、SPEC-PA-201／202

**基本フロー（記録）**
1. 卸売業者 担当者が相対取引入力画面を開く（PC またはタブレット）。残数量のあるロットだけが選択肢に出る。
2. ロット（番号・品目・出荷者で検索）と買受人（コード・名称・カナで検索）を選ぶ。取引日は本日が初期値。
3. 買受人または取引日を選ぶと、共通の取引権限チェックが動き、「✓ 取引可」または「✕ 取引不可」と理由、許可・承認の状態、根拠の規程条文を表示する。確認が終わるまで登録ボタンは押せない。
4. 数量と単価（税抜）を入力すると、金額（⌊数量 × 単価⌋）が参考表示される。
5. 「登録する」を押すと、サーバーで権限を再チェックし、金額を計算して「確定」として保存する。ロットの残数量が減り、「取引番号 n を登録しました（¥…）」と表示される。同じロットに残数量があれば、ロットを残したまま次の入力に移れる。

**基本フロー（例外登録と承認）**
1. 権限チェックが「✕」で、理由が例外を認めるもの（許可・承認の期限切れ、未取得〔停止・取消を除く〕、権限区分の不可）なら、「例外として登録」を選び、理由（例：電話で合意済み、承認更新の手続き中）を書いて登録する。
2. 取引は「承認待ち」で保存され、ロットの数量を確保する（二重販売を防ぐ）が、仕切には入らない。
3. 市場管理者が例外承認画面で、取引日時点の参加者の状態と許可を確認し、理由を書いて**承認**（「確定」になり、次の仕切から含まれる）または**却下**（取消され、数量はロットへ戻る）する。
4. 承認待ちのまま仕切を作っても、その取引は含まれない。後で承認された取引はその後の仕切に入る。仕切画面は未処理の承認待ち件数を警告する（E-04-S01）。

**基本フロー（取消・訂正）**
1. 直近の取引一覧で、仕切前の「確定」取引の「取消・訂正」を押し、理由を書いて確定する。
2. 取引は「取消」になり、数量はロットへ戻る。訂正は取消のあと正しい内容で再入力する。

**代替・例外フロー**
- 例外を認めない理由（参加者の停止、買受人でない、規程の未設定、許可の停止・取消）：例外登録は選べず、登録できない。
- 確認から保存までの間に参加者の状態や規程が変わった：保存せず、新しい理由を表示する（サーバーで必ず再チェック）。
- 2 人が同じロットを同時に売り、残数量を超える：後の登録を拒否し M_21 を表示、残数量を再表示する。
- 例外登録の理由が空：M_34。保存時に理由が例外不可に変わった：M_35。
- 取引日が未来日、8 日以上前、またはロットの市場日より前：登録しない。
- 数量が残数量を超える・単位に合わない（kg は小数 1 桁、箱・尾は整数）・単価が 0 以下：欄の横にエラー。
- 仕切済み・取消済み・承認待ちの取引の取消：拒否し M_32／M_31／M_39 を表示。
- 権限チェックが通信エラーで終わらない：登録ボタンを押せないままにし、再選択を促す。
- 通信障害：紙で記録し、復旧後に取引日を過去日（7 日前まで）にして入力する。権限はその取引日時点で判定される（NFR-003）。

## 7. データ要件

> 型・桁数・制約は基本設計で確定する。

| 項目 | 取得元 | 表示のみ／編集可 | 備考 |
| --- | --- | --- | --- |
| 取引番号 | システム採番 | 表示のみ | **システム全体で連番**（日ごとに戻さない）。仕切・売掛金の照合に使う |
| 販売チャネル | 固定（相対取引） | 表示のみ | せりは E-03-S02 |
| ロット | ロット（E-02-S01） | 登録時に選択 | 残数量 > 0、取消されていないもの |
| 買受人 | 参加者台帳（E-01-S01） | 登録時に選択 | コード・名称・カナ・種別を表示 |
| 数量 | 本画面で入力 | 登録時に入力 | 0 より大きく残数量以下。単位はロットに従う（kg は小数 1 桁、箱・尾は整数） |
| 単価（税抜） | 本画面で入力 | 登録時に入力 | **円単位の整数、1〜9,999,999**（ADR-006） |
| 金額（税抜） | サーバーで計算 | 表示のみ | ⌊数量 × 単価⌋（円未満切捨て）。画面の値は参考表示で、送信しない |
| 取引日 | 本画面で入力 | 登録時に入力 | 初期値＝本日（JST）。本日〜7 日前、かつロットの市場日以降 |
| 権限チェック結果 | 共通権限チェック | 表示のみ | 可否、理由コード（M_10〜M_16）、例外可否、許可区分・許可番号・有効期限、規程条文と適用開始日、「仮」表示 |
| 状態 | システム | 表示のみ | 確定／承認待ち／却下／取消 |
| 例外登録の理由 | 本画面で入力 | 例外登録時に入力（必須） | |
| 承認・却下の判断、理由、判断者、判断日時 | 例外承認画面 | 市場管理者が入力（理由必須） | |
| 取消理由・取消者・取消日時 | 取消操作 | 取消時に入力（理由必須） | 取引は削除しない（R-09） |
| 登録者・登録日時 | システム | 表示のみ | 監査ログにも記録 |

- 入力：ロット（E-02-S01）、参加者・許可（E-01-S01）、取引権限・種別区分（E-01-S04）。
- 出力：確定取引は仕切（E-04-S01）、売掛金（E-04-S02）、照会・帳票（E-05）の元データになる。共通権限チェックは E-03-S02、E-01-S01 が使う。

## 8. 技術的制約・非機能面の考慮事項

- **対象端末**：事務所の PC（キーボードショートカットあり）と売場のタブレット。レスポンシブで同じ機能を提供する。
- **権限チェックは DB に 1 つだけ**：画面の事前表示と保存処理は同じ判定関数を使い、保存時に必ず再判定する（ADR-002、R-06）。判定は取引日を基準とし、本日ではない。
- **応答時間**：権限チェックの結果は**約 1 秒以内**に表示する（登録ボタンの解除を待たせないため）。登録は NFR-001 の 3 秒程度以内。古い問い合わせの結果は破棄し、最後に選んだ買受人の結果だけを表示する。
- **同時販売**：ロットの残数量を保存時にロックして減算し、残数量を超える登録は拒否する。最大 10 名の同時入力でも二重販売しない。
- **NFR-005 計算精度**：金額は円単位の整数でサーバーが計算し、⌊数量 × 単価⌋ とする（ADR-006）。画面の金額は送信しない。
- **NFR-004 セキュリティ**：記録・取消は卸売業者 担当者、例外の承認・却下は市場管理者だけ（画面と DB の両方でチェック）。記録・例外登録・承認・却下・取消はすべて監査ログに残る。
- **通知**：承認待ちの件数を市場管理者のメニューにバッジで表示する。メール通知は行わない。
- **NFR-003 運用性**：通信障害時は紙で記録し、復旧後に取引日を過去日として入力する。権限はその日付時点で判定する。
- **NFR-006 法令・規程**：権限チェックは業務規程パラメータ（E-01-S04）に従い、根拠の規程条文を画面に表示する。
- 取引は削除しない（R-09）。日次バックアップの対象（NFR-007）。

## 9. 受入基準

**記録**
- [ ] Given 卸売業者 担当者がログインしている、When 相対取引入力画面を開く、Then ロットの選択肢には残数量があり取消されていないロットだけが出る。
- [ ] Given 取引可の買受人、When 数量 12.5 kg・単価 1,980 円で登録する、Then 「確定」として保存され、金額は 24,750 円（⌊12.5 × 1,980⌋）、ロットの残数量が 12.5 減り、取引番号が連番で振られる。
- [ ] Given 数量 3.3 kg・単価 333 円、When 登録する、Then 金額は 1,098 円（1,098.9 の円未満切捨て）で、画面から送った金額ではなくサーバーの計算値が保存される。
- [ ] Given 数量が残数量を超える、単位に合わない（箱で 1.5 など）、または単価が 0 以下・小数、When 登録する、Then 欄の横にエラーが表示され保存されない。
- [ ] Given 取引日が未来日、8 日以上前、またはロットの市場日より前、When 登録する、Then 保存されない。

**共通権限チェック**
- [ ] Given 買受人を選ぶ、When 選択が確定する、Then 約 1 秒以内に「✓ 取引可」または「✕ 取引不可」と理由・許可区分・許可番号・有効期限・規程条文・適用開始日が表示され、結果が出るまで登録ボタンは押せない。
- [ ] Given 停止中の参加者、買受人でない種別、規程が未設定、許可／承認がない・期限切れ、チャネル × 権限区分が不可の各ケース、When チェックする、Then それぞれ決められた理由（M_10〜M_16）が R-06 の順序で返る。
- [ ] Given 取引日に過去日を指定、When チェックする、Then 本日ではなくその取引日時点の許可と規程で判定される。
- [ ] Given 画面では取引可、When 保存までの間に参加者が停止される、Then 保存されず新しい理由が表示される。
- [ ] Given せり（E-03-S02）と参加者台帳（E-01-S01）、When 取引可否を判定する、Then 本ストーリーと同じ判定関数を使い、同じ入力に同じ結果を返す。

**例外登録と承認**
- [ ] Given 理由が例外可（期限切れ・未取得〔停止・取消を除く〕・権限区分の不可）、When 「例外として登録」を選び理由を書いて登録する、Then 「承認待ち」で保存され、ロットの残数量は減るが、仕切の対象には含まれない。
- [ ] Given 理由が例外不可（停止・買受人でない・規程未設定・許可の停止／取消）、When 画面を見る、Then 「例外として登録」は表示されず登録できない。API を直接呼んでも M_35 で拒否される。
- [ ] Given 例外登録の理由が空、When 登録する、Then M_34 が表示され保存されない。
- [ ] Given 承認待ちの取引、When 市場管理者が理由を書いて承認する、Then 「確定」になり、その後に作る仕切に含まれる。When 却下する、Then 「却下」（取消）になり、数量がロットへ戻る。
- [ ] Given 承認待ちの取引がある、When 市場管理者がメニューを見る、Then 承認待ちの件数がバッジで表示される。

**同時操作・取消・権限・監査**
- [ ] Given 残数量 10 kg のロット、When 2 名が同時に 8 kg ずつ登録する、Then 1 件だけ保存され、もう一方は M_21 で拒否されて残数量が再表示される。
- [ ] Given 仕切前の確定取引、When 理由を書いて取消す、Then 「取消」になり数量がロットへ戻る。仕切済み・取消済み・承認待ちの取引の取消は M_32／M_31／M_39 で拒否される。
- [ ] Given 市場管理者、When 相対取引入力画面を開く、Then 入力フォームは表示されず直近の取引だけが見える。記録・取消の API を直接呼んでも M_02 になる。卸売業者 担当者は例外の承認・却下ができない。
- [ ] Given 記録・例外登録・承認・却下・取消、When 実行する、Then 実行者・日時・内容・理由が監査ログに残る。
