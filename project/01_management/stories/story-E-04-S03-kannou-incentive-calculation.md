## 2. ユーザーストーリー

卸売業者 担当者として、毎月、期限までに全額を支払った請求期間について仲卸・売買参加者の完納奨励金を自動で計算・確定し、翌月の請求から相殺したい。なぜなら、手計算をなくし、買受人に問われたときに請求期間ごとの対象・対象外と理由を明確な根拠として示したいからだ。

## 3. 背景・目的

- **現状**：完納奨励金は入金台帳から手計算している（提案書、system-overview §2 #4。後者は QA-001 で顧客確認中）。手間がかかり、誤りが買受人との争いになりやすい。
- **目的 1**：卸売業者に買受代金を支払う**仲卸・売買参加者**のうち、期限までに全額を支払った買受人について、月ごとに完納奨励金を自動で計算する。率は期間（月）ごとの奨励金率（業務規程パラメータ、E-01-S04）、全額期限内支払いの判定は E-04-S02 の完納フラグを使う（system-overview §3 #4）。
- **目的 2**：確定した奨励金を翌月の請求から相殺する（反映は E-04-S02）。
- **最も重視する価値**：**買受人に問われたときに示せる明確な根拠**。買受人ごとに、どの請求期間が対象になり、どれが対象外になったか、その理由（期限後の入金、不足など）を明細で示し、争いを防ぐ。手計算との差はゼロにする（NFR-005）。

## 4. 対象ユーザー

| ROLE-ID | ロール | 利用場面 | 権限 |
| --- | --- | --- | --- |
| ROLE-002 | 卸売業者 担当者 | 毎月、対象月の最後の支払期限が過ぎた後に、事務所の PC で前月分を計算し、内容を確認して確定する。買受人に問われたら明細を見せる | 計算・確定・確定の取消・明細の閲覧と印刷 |
| ROLE-001 | 市場管理者 | 事務所の PC で計算結果と明細を確認する | 閲覧のみ |

- 承認フローは設けない（卸売業者 担当者が確定する。role-list の権限どおり）。
- 買受人はログインしない。明細は印刷または PDF で渡す。

## 5. スコープ

**対象内**
- **月次の計算**：対象月の請求期間（E-04-S02）のうち、**請求期間ごとに**完納フラグが立っているもの（期限までに全額支払い）だけを対象とし、その期間の**税抜の取引金額**の合計に、対象月に有効な奨励金率（E-01-S04）を掛ける。端数は買受人ごとの月合計で切り捨てる。1 つの請求期間が延滞でも、他の請求期間の分は対象になる
- 対象者：仲卸・売買参加者（第一種の買受人）
- **明細（根拠）**：買受人ごとに、請求期間、取引金額、支払期限、全額入金日、対象／対象外と理由（期限後の入金、不足額など）、率、奨励金額を一覧で示し、印刷・PDF 保存できる（仕切書と同じ印刷方式）
- 確定：卸売業者 担当者が内容を確認して確定する。確定した金額を E-04-S02 が翌月の請求から相殺する
- 確定の取消（理由必須）と再計算。翌月の請求書が未発行の場合だけ可能

**対象外**
- 段階的な率（金額帯ごとの率）や個別の例外ルール：見積の前提外（見積 v2 のリスク「完納奨励金の計算式が一律の率より複雑」+3〜5 人日）。必要なら変更要求
- 奨励金の現金払い・振込：相殺のみ（提案書の前提、Q-07、Q-25）
- 請求からの相殺の反映 → E-04-S02
- 第二種の買受人（買出人）：卸売業者への支払いがないため対象外

## 6. 主な業務フロー

> LAB-4 に画面仕様はない（market-rule-catalog「完納奨励金は未設計」）。基本設計で作成する。

**基本フロー（計算と確定）**
1. 対象月に締め日がある請求期間をその月に属するものとする。対象月の最後の支払期限が過ぎると、計算できるようになる（それより前は計算ボタンを無効にする）。
2. 卸売業者 担当者が事務所の PC で対象月を選び「計算」を押す。サーバーが買受人ごとに、完納フラグの立った請求期間の税抜取引金額を合計し、対象月の奨励金率を掛け、月合計で切り捨てる。
3. 結果の一覧（買受人、対象金額、率、奨励金額）と、買受人ごとの明細（請求期間、取引金額、支払期限、全額入金日、対象／対象外と理由）を確認する。
4. 「確定」を押すと、奨励金額と使った率が記録され、E-04-S02 が翌月の請求期間から相殺する。
5. 買受人に問われたら、明細を画面で見せるか、印刷・PDF 保存して渡す。

**基本フロー（確定後の変更）**
1. 確定後に入金の取消などで完納フラグが変わった場合、確定済みの結果に「再計算が必要」と警告を表示する。
2. 翌月の請求書が未発行なら、担当者が理由を書いて確定を取消し、再計算して確定し直す。
3. 翌月の請求書が発行済みなら、確定の取消はできない。差額は次の月の計算で調整額として扱う（調整の行として明細に残す）。

**代替・例外フロー**
- 対象月の最後の支払期限より前に計算しようとする：計算できない。
- 対象月に有効な奨励金率が設定されていない：計算できずエラーを表示する。
- 対象となる請求期間が 1 件もない買受人：奨励金 0 円として一覧に載せ、明細に対象外の理由を示す。
- 同じ月をもう一度確定しようとする：拒否する（確定は月に 1 回。やり直しは取消してから）。
- 市場管理者が計算・確定・取消を試みる（API の直接呼び出しを含む）：M_02、DB に変更を残さない。

## 7. データ要件

> 型・桁数・制約は基本設計で確定する。金額はすべて円単位の整数（ADR-006）。本ストーリーで新しく入力するデータは確定の取消理由だけで、ほかは既存データからの計算結果。

| 項目 | 取得元 | 表示のみ／編集可 | 備考 |
| --- | --- | --- | --- |
| 対象月 | 本画面で選択 | 計算時に選択 | 対象月の最後の支払期限の後だけ計算可能 |
| 請求期間・税抜取引金額・支払期限・全額入金日・完納フラグ | E-04-S02 | 表示のみ | 締め日が対象月にある請求期間 |
| 奨励金率 | 業務規程パラメータ（E-01-S04） | 表示のみ | 対象月に有効な率。結果に記録し、後でパラメータが変わっても確定済みの金額は変わらない |
| 対象金額（買受人ごと） | サーバーで計算 | 表示のみ | 完納フラグの立った請求期間の税抜取引金額の合計 |
| 奨励金額（買受人ごと） | サーバーで計算 | 表示のみ | ⌊対象金額 × 率⌋（月合計で切り捨て）＋前月からの調整額 |
| 明細（請求期間ごと） | サーバーで計算 | 表示のみ | 対象／対象外と理由（期限後の入金、不足額）。印刷・PDF 保存可 |
| 状態 | システム | 表示のみ | 計算済み（未確定）／確定／取消／再計算が必要 |
| 確定者・確定日時 | システム | 表示のみ | 監査ログにも記録 |
| 取消理由・取消者・取消日時 | 確定の取消 | 取消時に入力（理由必須） | 確定結果は削除しない |
| 調整額 | サーバーで計算 | 表示のみ | 翌月の請求書発行後に判明した差額を次の月で調整 |

- 出力：確定した奨励金額を E-04-S02 へ（翌月の請求から相殺）。明細は買受人への説明資料。

## 8. 技術的制約・非機能面の考慮事項

- **対象端末**：事務所の PC ブラウザ。
- **計算はサーバーの 1 つの関数だけ**：計算・再計算は DB 側の同じ関数で行い、画面では再計算しない（ADR-002、ADR-006）。確定と率の記録は 1 つのトランザクションで行い、同じ月の二重確定を DB で防ぐ。
- **NFR-005 計算精度**：円単位の整数、月合計で切り捨て。IT/ST の合意テストケースと UAT の並行稼働で、手計算との差ゼロを確認する（overview KPI #2）。
- **根拠の再現性**：確定時の率と対象請求期間を記録し、後からパラメータや入金が変わっても、確定時点の明細を再表示できる。
- **印刷・PDF**：明細は A4 の印刷用ページとし、ブラウザの印刷ダイアログで PDF 保存する（仕切書と同じ方式）。
- **NFR-004 セキュリティ**：計算・確定・取消は卸売業者 担当者だけ（画面と DB の両方）。確定・取消は監査ログに残る。
- **NFR-001 性能**：1 か月分（買受人 20〜50 名）の計算は 3 秒程度以内。
- 確定結果は削除しない。日次バックアップの対象（NFR-007）。

## 9. 受入基準

**計算**
- [ ] Given 4 月の奨励金率 0.5%、仲卸 A の 4 月の請求期間が 3 つ（税抜 400,000 円・完納、300,000 円・完納、250,000 円・期限後入金）、When 4 月分を計算する、Then 対象金額 700,000 円、奨励金 3,500 円となり、3 つ目の期間は「対象外：期限後の入金」と明細に表示される。
- [ ] Given 対象金額 123,457 円、率 0.5%、When 計算する、Then 奨励金は 617 円（617.285 の切り捨て）になる。
- [ ] Given 支払期限までに 1 円でも不足した請求期間、When 計算する、Then その期間は対象外となり、不足額が理由として表示される。
- [ ] Given 第二種の買受人（買出人）、When 計算する、Then 対象者に含まれない。
- [ ] Given 対象月の最後の支払期限より前、または対象月に有効な率がない、When 計算しようとする、Then 計算できない。
- [ ] Given 対象の請求期間がない買受人、When 計算する、Then 奨励金 0 円として載り、明細に理由が示される。

**確定・相殺**
- [ ] Given 計算結果、When 確定する、Then 奨励金額と使った率が記録され、翌月の請求書（E-04-S02）で相殺額として差し引かれる。
- [ ] Given 確定済みの月、When もう一度確定しようとする、Then 拒否される。
- [ ] Given 確定後に業務規程の奨励金率が改定された、When 確定済みの明細を見る、Then 金額と率は確定時のまま変わらない。

**確定後の変更・根拠・権限**
- [ ] Given 確定後に入金が取消されて完納フラグが外れた、When 結果を見る、Then 「再計算が必要」と警告される。翌月の請求書が未発行なら、理由を書いて確定を取消し、再計算・再確定できる。
- [ ] Given 翌月の請求書が発行済み、When 確定を取消そうとする、Then 取消できず、差額は次の月の計算で調整額として明細に載る。
- [ ] Given 買受人ごとの明細、When 印刷または PDF 保存する、Then 請求期間ごとの対象／対象外、理由、率、奨励金額が A4 で崩れずに出力される。
- [ ] Given 市場管理者、When 計算・確定・取消しようとする（API の直接呼び出しを含む）、Then M_02 になり DB に変更が残らない。結果と明細は閲覧できる。
- [ ] Given 確定・確定の取消、When 実行する、Then 実行者・日時・内容・理由が監査ログに残る。
