## 2. ユーザーストーリー

市場管理者として、市場管理事務所と卸売業者の職員のログインアカウントを作り、ロールを割り当て、退職者などを利用停止にしたい。なぜなら、職員一人ひとりが自分のアカウントで操作し、誰が何をしたかを監査ログで追えるようにし、権限のない人が操作できないようにしたいからだ。

## 3. 背景・目的

- **現状**：システムがないためアカウントもない。2 つのロール（市場管理者／卸売業者 担当者）だけがログインする（role-list §1、ADR-009）。
- **目的 1**：職員ごとの個人アカウントを発行・管理する。取引・金銭の監査ログ（NFR-004）は個人を特定できる必要があるため、**共用アカウントは作らない**。
- **目的 2**：ロールの割当と利用停止で、操作できる人を市場管理者が管理する。
- ログインの仕組みとロールによる権限制御（RLS）は基本設計の基盤（見積 v2 の 2.4）で作る。本ストーリーはアカウントを管理する画面（見積 v2 の 3.5：FE 1・BE 1 人日）。

## 4. 対象ユーザー

| ROLE-ID | ロール | 利用場面 | 権限 |
| --- | --- | --- | --- |
| ROLE-001 | 市場管理者 | 事務所の PC で、職員の入社・異動・退職時にアカウントを作成・変更・停止する。頻度は月数回以下 | 全操作 |
| ROLE-002 | 卸売業者 担当者 | 利用しない（自分のパスワード変更のみ） | なし（role-list） |

- [ASSUMPTION] アカウント数は合計 20 名程度（§10 #1）。売場のタブレットは共用でも、ログインは個人のアカウントで行う。

## 5. スコープ

**対象内**
- アカウントの一覧（氏名・メールアドレス・ロール・状態で検索・絞り込み）
- アカウントの作成（PM 決定、2026-11-23）：氏名、メールアドレス、ロール（市場管理者／卸売業者 担当者）を入力すると、**招待メール**が届き、本人がパスワードを設定する
- ロールの変更、利用停止・再開（停止したアカウントはログインできない。削除はしない）
- パスワードを忘れたときは、ログイン画面から本人がメールで再設定する（PM 決定。全職員が業務用メールを持つことが前提、§10 #2）
- 自分のパスワード変更（全ロール）
- 最後の市場管理者を停止・降格できないようにする

**対象外**
- 仲卸・売買参加者・買出人のログイン（提案書のシナリオ S1、+23 人日）
- 2 段階認証、シングルサインオン
- ロールの追加・権限の細かな設定（2 ロール固定）
- ログイン基盤・RLS そのもの → 基本設計（見積 v2 の 2.4）

## 6. 主な業務フロー

**基本フロー**
1. 市場管理者がアカウント一覧から「新規作成」を押し、氏名・メールアドレス・ロールを入力して保存する。
2. 本人に招待メールが届き、リンクからパスワードを設定するとログインできる。
3. 異動ではロールを変更し、退職では理由を書いて利用停止にする。停止すると、そのアカウントは次の操作からログイン状態を失う。
4. パスワードを忘れた職員は、ログイン画面の「パスワードを忘れた場合」からメールで再設定する。

**代替・例外フロー**
- メールアドレスの重複、必須項目の未入力：保存せずエラーを表示する。
- 招待リンクの期限切れ：市場管理者が招待を再送する。
- 自分自身、または最後の有効な市場管理者を停止・降格しようとする：拒否する。
- 卸売業者 担当者がアカウント管理を開く・API を直接呼ぶ：画面は表示せず、API は M_02 で拒否する。

## 7. データ要件

> 型・桁数は基本設計で確定する。認証情報（パスワード）は認証基盤が管理し、アプリの DB には持たない。

| 項目 | 取得元 | 表示のみ／編集可 | 備考 |
| --- | --- | --- | --- |
| 氏名 | 本画面で入力 | 編集可 | 監査ログ・画面の操作者表示に使う |
| メールアドレス | 本画面で入力 | 作成時に入力 | ログイン ID。一意 |
| ロール | 本画面で選択 | 編集可 | 市場管理者／卸売業者 担当者 |
| 状態・停止理由 | 本画面で入力 | 編集可 | 招待中／有効／停止 |
| 最終ログイン日時 | 認証基盤 | 表示のみ | |
| 作成者・作成日時・更新者・更新日時 | システム | 表示のみ | |

## 8. 技術的制約・非機能面の考慮事項

- 事務所の PC ブラウザ。
- 認証は Supabase Auth を使う（提案書：本番も Next.js／Vercel／Supabase）。招待・パスワード再設定のメール送信も Supabase の機能を使う。
- **NFR-004 セキュリティ**：通信は TLS、パスワードは認証基盤がハッシュ化して保存する。アカウント管理は市場管理者だけ（画面と DB の両方）。作成・ロール変更・停止は監査ログに残る。停止したアカウントのセッションは無効にする。
- **NFR-006**：職員の氏名・メールアドレスは個人情報として扱う。
- アカウントは削除しない（監査ログの操作者を残すため）。

## 9. 受入基準

- [ ] Given 市場管理者、When 氏名・メールアドレス・ロールを入力してアカウントを作成する、Then 状態「招待中」で一覧に表示され、本人に招待メールが届く。本人がパスワードを設定すると「有効」になりログインできる。
- [ ] Given 既存と同じメールアドレス、When 作成する、Then 保存されずエラーが表示される。
- [ ] Given 卸売業者 担当者のアカウント、When ロールを市場管理者に変更する、Then 次の操作から市場管理者の画面と権限になる。
- [ ] Given 有効なアカウント、When 理由を書いて利用停止にする、Then そのアカウントはログインできず、ログイン中のセッションも無効になる。過去の監査ログには氏名が表示され続ける。
- [ ] Given 有効な市場管理者が 1 名だけ、When その人を停止または降格しようとする、Then 拒否される。自分自身の停止も拒否される。
- [ ] Given パスワードを忘れた職員、When ログイン画面から再設定を依頼する、Then メールのリンクから新しいパスワードを設定できる。
- [ ] Given 卸売業者 担当者、When アカウント管理の画面を開く、または API を直接呼ぶ、Then 画面は表示されず、API は M_02 で拒否される。自分のパスワード変更はできる。
- [ ] Given 作成・ロール変更・停止・再開、When 実行する、Then 実行者・日時・内容が監査ログに残る。
